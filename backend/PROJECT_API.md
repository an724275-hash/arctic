# API проектов и экспертизы

Все пути ниже имеют префикс `/api/v1`. Защищённые запросы используют заголовок `Authorization: Bearer <access_token>`. Идентификаторы — строки UUID, даты — ISO 8601 с часовым поясом.

## Проекты

| Метод и путь | Доступ и результат |
| --- | --- |
| `GET /projects?offset=0&limit=100` | Массив проектов: участник видит свои, педагог — работы принявших связь участников, эксперт — назначенные ему, администратор и комиссия — все. `limit`: 1–200. |
| `POST /projects` | Только участник; создаёт черновик, ответ `201`. |
| `GET /projects/{id}` | Доступ по правилам списка; возвращает проект, `files`, `nomination_title`, `participant_name`. |
| `PATCH /projects/{id}` | Только автор-участник и только черновик; частичное обновление, ответ `200`. |
| `DELETE /projects/{id}` | Только автор-участник и только черновик; удаляет запись и файлы, ответ `204`. |
| `POST /projects/{id}/submit` | Автор подаёт черновик, ответ `200`; нужны основной документ и действующая номинация, этап `projects` должен быть открыт. |
| `POST /projects/{id}/reopen` | Автор возвращает отклонённый проект в черновик, ответ `200`. |
| `POST /admin/projects/{id}/moderate` | Администратор допускает или отклоняет поданный проект, ответ `200`. |

Тело создания:

```json
{
  "title": "Арктический лёд",
  "abstract": "Краткое описание исследования и его результатов.",
  "nomination_id": "UUID",
  "video_url": "https://example.org/video"
}
```

`title`: 3–250 символов, `abstract`: 10–20 000. `video_url` необязателен, допускается только HTTPS без логина и пароля; `null` очищает ссылку. `PATCH` принимает те же поля, все необязательны; `null` для остальных полей запрещён. Неизвестные поля запрещены. Номинации: `GET /nominations`.

Ответ проекта содержит `id`, `user_id`, `nomination_id`, `title`, `abstract`, `video_url`, `status`, `moderation_comment`, `reviews_released`, `created_at`, `updated_at`, `submitted_at`. Дополнительные поля деталей перечислены в таблице. Профиль автора и его контакты в ответ не включаются.

Модерация: `{"status":"admitted","comment":""}` или `{"status":"rejected","comment":"Уточните метод исследования"}`. При отклонении причина обязательна: минимум 5 символов. Допустимые переходы:

```text
draft → submitted → admitted → reviewing → evaluated
                 ↘ rejected → draft
```

## Файлы

| Метод и путь | Назначение |
| --- | --- |
| `GET /projects/{id}/files` | Массив метаданных файлов доступного проекта. |
| `POST /projects/{id}/files` | `multipart/form-data`: поля `file` и `kind`; автор черновика, ответ `201`. |
| `DELETE /projects/{id}/files/{file_id}` | Автор черновика; ответ `204`. |
| `GET /files/{file_id}/download` | Приватное скачивание с Bearer-токеном; ответ — файл с `Content-Disposition: attachment`. |

`kind=document` (по умолчанию): PDF/DOCX; `presentation`: PDF/PPTX; `video`: MP4/WebM. Максимальный размер задаёт `MAX_UPLOAD_MB`, по умолчанию 30 МБ. Проверяются расширение, сигнатура и структура Office; исполняемые вложения и макросы в Office запрещены.

Метаданные: `id`, `project_id`, `original_name`, `media_type`, `size_bytes`, `kind`, `created_at`. Внутреннее имя и путь хранения не передаются. Оригинальное имя очищается от путей и управляющих символов. Файл можно скачать только с теми же правами, которые дают доступ к проекту. Для скачивания из браузера используйте авторизованный `fetch`, затем Blob URL; обычная ссылка не добавляет Bearer-токен.

## Назначения и рецензии

| Метод и путь | Назначение |
| --- | --- |
| `POST /admin/projects/{id}/assign` | Администратор: `{"expert_ids":["UUID","UUID"]}`. Только действующие эксперты, проект допущен или уже на экспертизе. |
| `POST /admin/projects/auto-assign` | Администратор: `{"count":2,"project_ids":["UUID"]}`. `count`: 1–10 — целевое число экспертов на проект. Без `project_ids` обрабатывает все доступные проекты; распределяет с учётом нагрузки. |
| `GET /expert/assignments?offset=0&limit=100` | Эксперт: массив собственных назначений с проектами и собственными рецензиями; `limit`: 1–200. |
| `POST /expert/assignments/{id}/review` | Назначенный эксперт отправляет окончательную рецензию, ответ `201`. `PUT` — синоним этого метода. |
| `GET /projects/{id}/reviews` | Доступные рецензии проекта; правила публикации ниже. |
| `POST /admin/projects/{id}/publish` | Администратор публикует результаты завершённой экспертизы; ответ — проект с `reviews_released=true`. |

Оба метода назначения возвращают `{"assigned":2,"assignments":[...]}`. Каждый элемент содержит `id`, `project_id`, `expert_id`, `created_at`. Повторное назначение не создаёт дубликаты; массив ответа содержит только новые назначения. Список эксперта дополнительно содержит `project`, `review_submitted` и `own_review` (`null` до отправки).

Действующие критерии: `GET /criteria`. Рецензия:

```json
{
  "scores": {"UUID_критерия_1": 7, "UUID_критерия_2": 9},
  "comment": "Сильная постановка задачи; необходимо подробнее раскрыть метод."
}
```

Нужно передать ровно все действующие критерии. Оценки — конечные числа от 0 до `max_score` соответствующего критерия; комментарий — 10–20 000 символов. Ответ содержит `id`, `assignment_id`, `project_id`, `expert_id`, `criteria_snapshot`, `scores`, `comment`, `weighted_score`, `submitted_at`. Снимок каждого критерия сохраняет `id`, `name`, `description`, `max_score`, `weight`. Итог: `100 × Σ(score / max_score × weight) / Σ(weight)`, округлённый до четырёх знаков. Изменение критериев не меняет сохранённую рецензию.

Рецензию нельзя изменить после отправки. Пока эксперт не отправил собственную рецензию, он не видит оценки коллег. Автор и связанный педагог получают пустой массив до публикации; затем видят все рецензии. Администратор и комиссия видят поступившие рецензии. Проект становится `evaluated`, когда ответили все назначенные эксперты; до этого публикация запрещена. Повторная публикация безопасна и не дублирует уведомление.

## Ошибки

Ошибка возвращает `detail` (строку либо массив ошибок валидации). `401` — нет действующей авторизации; `403` — нет прав; `404` — объект или файл отсутствует; `409` — неподходящий статус, закрытый этап или уже отправленная рецензия; `413` — превышен лимит файла/запроса; `422` — некорректные поля, формат файла, оценки, номинация или состав экспертов. Перед повторной отправкой после `409` перечитайте состояние объекта.
