# Аккаунты и администрирование

Префикс всех маршрутов — `/api/v1`. Точные схемы и примеры доступны в `/docs`. JSON-запросы используют `Content-Type: application/json`; авторизация — `Authorization: Bearer <access_token>`. Ошибки возвращают `detail`; даты — ISO 8601, даты этапов и защит обязательно содержат часовой пояс.

## Аккаунт

`POST /auth/register` принимает `email`, `password`, `full_name`, `role` (`participant` по умолчанию или `teacher`), `consent: true`; дополнительно `birth_date`, `school`, `grade` (1–12), `region`, `guardian_name`, `guardian_email`, `guardian_consent`. Для участника дата рождения обязательна; возраст должен быть 6–120 лет. Для несовершеннолетнего обязательны данные представителя и `guardian_consent: true`. Если указана дата рождения наставника, ему должно быть не менее 18 лет. Регистрироваться можно только в открытый этап `registration`. Пароль содержит 10–256 символов, буквы и цифры. Роли `expert`, `commission`, `admin`, `partner` публичная регистрация не принимает.

Регистрация (201), `POST /auth/login` с `{email,password}`, форма `POST /auth/token` с `username=<email>&password=...` и `POST /auth/refresh` с `{refresh_token}` возвращают:

```json
{
  "access_token": "...",
  "refresh_token": "...",
  "token_type": "bearer",
  "expires_in": 1800,
  "user": {"id": "...", "email": "...", "full_name": "...", "role": "participant"}
}
```

`user` также включает профиль, `consent_at`, `guardian_consent_at`, `email_verified`, `is_active`, `created_at`. Хеш пароля и версия отзыва токенов не возвращаются. При обновлении сессии клиент заменяет оба токена. Повторное использование отозванного refresh-токена отзывает все сессии аккаунта. `POST /auth/logout` требует Bearer, не требует тела и завершает все сессии. Истёкшая, отозванная или отключённая сессия получает 401.

| Маршрут | Запрос и результат |
|---|---|
| `POST /auth/forgot-password` | `{email}`; одинаковый ответ для существующей и неизвестной почты |
| `POST /auth/reset-password` | `{token,password}`; одноразовый токен живёт 30 минут, смена пароля отзывает все сессии |
| `POST /auth/verify-email` | `{token}`; одноразовый токен живёт 24 часа |
| `POST /auth/resend-verification` | Bearer; ставит новое подтверждение в очередь, прежняя ссылка перестаёт действовать |
| `GET /users/me` | Текущий профиль |
| `PATCH /users/me` | Необязательные `full_name`, `school`, `grade`, `region`, `guardian_name`, `guardian_email`, `guardian_consent` |

Почта, роль и дата рождения через изменение профиля не меняются. Для несовершеннолетнего нельзя очистить данные представителя; изменение этих данных требует нового `guardian_consent: true` и обновляет сохранённую дату согласия. Поле `full_name` не принимает `null` или пустую строку. Время согласия фиксирует заявление пользователя в форме; отдельное подтверждение личности представителя не реализовано.

Письма сохраняются в `outbox`, API их самостоятельно не отправляет. Токены восстановления и подтверждения отсутствуют в HTTP-ответах. Ссылки используют `FRONTEND_URL` и маршруты `/reset-password?token=...`, `/verify-email?token=...`, `/teacher/confirm?token=...`. Обработку этих страниц должен предоставить клиент.

## Наставники и уведомления

| Маршрут | Доступ и контракт |
|---|---|
| `GET /teachers` | Авторизованный пользователь; `limit` 1–100, `offset`; список `{id,full_name,school,region}` |
| `GET /teachers/link` | Участник; `null` или `{id,status,teacher,created_at}` |
| `POST /teachers/invite` | Участник, `{email}`; 202 и сообщение. Разрешена ещё не зарегистрированная почта наставника |
| `POST /teachers/confirm` | Наставник, `{token}`; почта аккаунта должна совпадать с приглашением |
| `DELETE /teachers/link` | Участник; удаляет связь и отменяет оставшиеся приглашения |
| `GET /teachers/students` | Наставник; только принявшие связь участники, `limit` 1–100, `offset` |
| `GET /notifications` | Только собственные уведомления; `unread_only`, `limit` 1–100, `offset` |
| `POST /notifications/read-all` | Отмечает собственные уведомления прочитанными |
| `PATCH /notifications/{id}/read` | Только своё уведомление; чужое или отсутствующее — 404 |

Приглашение живёт 7 дней и используется один раз. Новое приглашение отменяет прежнее; действующая связь сохраняется до принятия нового приглашения. Подтверждённая связь имеет `status: accepted`. Список учеников содержит `id`, `full_name`, `school`, `grade`, `region`, `linked_at`; сведения о представителях не раскрываются.

## Администратор

Все `/admin/...` ниже доступны только `admin`, кроме `/admin/stats` и `/admin/rankings`, доступных также `commission`. Списки пользователей, рейтинга, сообщений, очереди и аудита имеют оболочку `{items,total,limit,offset}`; `limit` 1–200, по умолчанию 50. Остальные списки возвращают массив.

| Маршрут | Контракт |
|---|---|
| `GET /admin/users` | Фильтры `q` по имени/почте, `role`, `is_active`, пагинация |
| `POST /admin/users` | `{email,full_name,password,role}`; роли `teacher`, `expert`, `commission`, `admin`, `partner`; 201 и публичный профиль |
| `PATCH /admin/users/{id}` | Необязательные `role`, `is_active`; при изменении отзывает сессии |
| `DELETE /admin/users/{id}` | Обезличивает и отключает аккаунт, отзывает сессии |
| `GET, POST /admin/nominations` | Создание: `{title,description?,is_active?}` |
| `PUT, PATCH /admin/nominations/{id}` | Переданные поля номинации; `title` необязателен при изменении |
| `DELETE /admin/nominations/{id}` | Удаление; при наличии проектов — отключение |
| `GET, POST /admin/criteria` | Создание: `{name,description?,max_score?,weight?,is_active?}`; `max_score` и `weight` больше 0 и не больше 1000 |
| `PUT, PATCH /admin/criteria/{id}` | Переданные поля критерия; `name` необязателен при изменении |
| `DELETE /admin/criteria/{id}` | Отключение; снимки критериев в выставленных оценках сохраняются |
| `GET /criteria` | Публичный список активных критериев |
| `GET /admin/stages` | Все этапы |
| `PUT /admin/stages/{slug}` | `{title,starts_at?,ends_at?,is_enabled?,position?}`; создаёт или заменяет настройки, начало строго раньше конца |
| `GET /admin/stats` | Счётчики пользователей, проектов, оценок, попыток, успешных тестов, документов; группы `regions`, `schools`, `roles`, `project_statuses`, `nominations`, `signups_daily` |
| `GET /admin/rankings` | Фильтр `nomination_id`, пагинация. Только `evaluated` проекты, у которых завершены все назначенные оценки; `rank`, `average_score`, `review_count`, `reviews_released`, объекты `project`, `participant`, `nomination` |
| `GET /admin/export/users.csv` | Пользователи: ID, имя, почта, роль, школа, класс, регион, активность, дата регистрации |
| `GET /admin/export/projects.csv` | Проекты: ID, название, участник, номинация, статус, даты создания и подачи |

Последнего активного администратора нельзя отключить, удалить или понизить. Изменения ролей сериализуются транзакционной блокировкой PostgreSQL. Обезличенный аккаунт нельзя активировать повторно. Перевод в участники требует существующей даты рождения и согласия; перевод несовершеннолетнего в наставники запрещён. CSV содержит UTF-8 BOM, а потенциальные формулы экранируются апострофом.

Рейтинг использует среднее `Review.weighted_score` в шкале 0–100, округлённое до двух знаков. Равные средние получают одинаковое место без пропусков: 1, 1, 2. При равенстве порядок стабилен по ID проекта. Места вычисляются до пагинации; при фильтре номинации — внутри выбранной номинации. Неопубликованные оценки доступны в этом административном рейтинге.

`DELETE /admin/users/{id}` очищает только профиль аккаунта. Конкурсные проекты, загруженные файлы, оценки, документы, история аудита и переписка сохраняются. Это не полное удаление всех персональных данных из системы.

## Защиты, документы и сообщения

| Маршрут | Контракт |
|---|---|
| `POST /admin/defenses` | `{project_id,starts_at,join_url,description?}`; 201. Проект должен иметь статус `admitted`, `reviewing` или `evaluated` |
| `PUT /admin/defenses/{id}` | Те же поля; изменяет назначенную защиту |
| `GET /defenses` | Защиты собственных проектов, связанных учеников или назначенных эксперту проектов; администратор видит все |
| `POST /admin/certificates` | `{user_id,kind,title}`; `kind: diploma` для участника или `teacher_thanks` для наставника; 201, реквизиты и ссылки скачивания/проверки |
| `GET /admin/messages` | Фильтр `status`, пагинация; обращения из контактной формы |
| `PATCH /admin/messages/{id}` | `{status}`: `new`, `in_progress`, `resolved`, `closed` |
| `POST /admin/announcements` | `{title,body,roles,email?}`; уведомления активным аккаунтам выбранных ролей, `email` по умолчанию `false`; ответ `{notifications_created,emails_queued}` |
| `GET /admin/outbox` | Фильтр `status`, пагинация; только метаданные, без тела письма и текста ошибки доставки |
| `GET /admin/audit` | Фильтр `action`, пагинация; журнал административных и значимых действий |

Рассылка с `email: true` только добавляет письма в очередь; отправку выполняет отдельно включённый почтовый обработчик. Назначение защиты и выдача документа создают внутреннее уведомление получателю.
