# Тестирование и сертификаты: подключение интерфейса

Все пути ниже начинаются с `/api/v1`. Защищённые запросы принимают `Authorization: Bearer <access_token>`. Даты передаются в ISO 8601 с часовым поясом. Полные схемы доступны в `/docs`.

## Начало и продолжение теста

- `GET /quiz/config` — открытые настройки: `title`, `question_count`, `duration_seconds`, `pass_percent`, `max_attempts`, `enabled`, `certificate_policy`.
- `POST /quiz/attempts` — начать тест без тела запроса. Если уже есть незавершённая попытка, сервер вернёт её с прежним сроком окончания. Нужна роль `participant`, заполненное ФИО и согласие на обработку данных.
- `GET /quiz/attempts?limit=50&offset=0` — свои попытки, от новых к старым.
- `GET /quiz/attempts/{attempt_id}` — состояние своей попытки.

Новая попытка недоступна вне настроенного этапа `testing`, при выключенном тесте или исчерпанном лимите (`409`). Уже начатую попытку можно продолжить и отправить после закрытия этапа, пока не истёк её собственный таймер. Недостаток активных вопросов в банке возвращает `503`.

Ответ попытки содержит `id`, `started_at`, `expires_at`, `server_now`, `seconds_remaining`, `status`, `config`, `questions`, `answers`, `submitted_at`, `score_percent`, `passed`, `certificate`. Статус: `active`, `submitted` или `expired`.

Вопрос: `id`, `text`, `options: [{id, text}]`, `topic`, `difficulty`, `multiple_choice`. При `multiple_choice: true` используйте флажки, иначе один выбор. В активной попытке правильные ответы и пояснения отсутствуют. Порядок вопросов случайный, состав и условия попытки зафиксированы при старте.

## Таймер и отправка

Показывайте таймер по разнице `expires_at - server_now`, отсчитывая прошедшее время локально. При восстановлении вкладки заново запросите попытку. Локальный таймер служит отображению: окончательное время проверяет сервер.

Для автосохранения вызывайте `PATCH /quiz/attempts/{attempt_id}/answers` после изменения выбора; для окончательной отправки — `POST /quiz/attempts/{attempt_id}/submit`. Оба принимают одинаковое тело:

```json
{
  "answers": {
    "uuid-вопроса-1": ["a"],
    "uuid-вопроса-2": ["a", "c"]
  }
}
```

Ключи берите из `questions[].id`, значения — из `options[].id`. Пропущенный вопрос или пустой массив считаются неверным ответом. Несколько вариантов засчитываются только при точном совпадении всего набора. Все вопросы имеют одинаковый вес. Не передавайте баллы или признак прохождения: сервер вычисляет их сам; неизвестные поля и варианты отклоняются (`422`).

Каждый `PATCH` **целиком заменяет** сохранённый набор ответов: передавайте все текущие ответы, включая ранее выбранные. Пустой `answers: {}` очищает черновик. Сохраняйте запросы последовательно и показывайте состояние сохранения: параллельные запросы блокируются на сервере, но порядок их прибытия не обязан совпадать с порядком действий пользователя. Срок теста при сохранении не продлевается. Сервер возвращает активную попытку с `answers`, без баллов и правильных вариантов. При возобновлении восстановите выбор из этого поля.

Ответ имеет ту же схему попытки и дополнительно раскрывает `correct_option_ids`, `selected_option_ids`, `is_correct`, `explanation` для каждого вопроса. `score_percent` округлён до двух знаков; прохождение сравнивается с зафиксированным порогом до округления. Повторная отправка возвращает уже сохранённый результат и тот же сертификат.

После дедлайна новые ответы не принимаются: попытка завершается с последним сохранённым набором, получает статус `expired` и расходует одну попытку. Если ничего не сохранялось, оценивается пустой набор. Поздний `PATCH` или `POST` возвращает завершённый результат и не применяет новые варианты. Просмотр просроченной попытки и следующий запуск также завершают её на сервере. При окончании таймера можно запросить попытку, чтобы получить результат по сохранённым ответам.

## Сертификаты

Каждая завершённая попытка получает ровно один документ: `test_passed` при достижении порога или `test_participation` за участие. Участие не означает успешное прохождение. Для истёкшей попытки действует тот же порог по сохранённым ответам; при установленном администратором нулевом пороге любой результат считается проходным.

- `GET /certificates?limit=50&offset=0` — свои документы.
- `GET /certificates/{certificate_id}/download` — PDF владельцу или администратору. Для кнопки скачивания используйте авторизованный `fetch`, затем `Blob` и временный URL: обычная ссылка не передаёт Bearer-токен.
- `GET /certificates/verify/{token}` — открытая проверка по непредсказуемому токену из `verification_url`/QR. Возвращает `valid`, `number`, `kind`, `title`, `issued_at`, `recipient` (имя замаскировано). Неверный токен — `404`.

Объект документа содержит `id`, `number`, `kind`, `title`, `attempt_id`, `issued_at`, `download_url`, `verification_url`. Администратор также может выдавать `diploma` и `teacher_thanks`; PDF отображает отдельные заголовки «ДИПЛОМ» и «БЛАГОДАРНОСТЬ».

`PUBLIC_BASE_URL` задаёт внешний адрес API для QR-кода. В PDF встраивается локальный кириллический TTF-шрифт из `CERTIFICATE_FONT_PATH` либо установленный Arial/DejaVu/Liberation. Если шрифт отсутствует, скачивание возвращает `503`.

## Банк вопросов и настройки

Только администратору доступны `GET/POST /admin/questions`, `PUT/DELETE /admin/questions/{id}` и `GET/PUT /admin/quiz-config`. `PUT` передаёт полный объект. У списков максимальный `limit` — `200`.

Вопрос: `text`, `options`, `correct_option_ids`, `topic`, `difficulty` (`easy`, `medium`, `hard`), `is_active`, `explanation`. Вариантов от 2 до 8, идентификаторы уникальны; правильные ответы должны входить в список вариантов. Удаление и изменение вопроса не меняет уже начатые попытки.

Настройки: `title`, `question_count` (1–100), `duration_seconds` (30–14400), `pass_percent` (0–100), `max_attempts` (1–20), `enabled`. Для включённого теста число вопросов не может превышать активный банк. Изменение настроек действует на новые попытки.
