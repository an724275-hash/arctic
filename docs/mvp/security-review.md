# Проверка безопасности MVP, 14 октября 2026

Проверены настройки запуска, авторизация JWT, ролевые зависимости, загрузки документов, HTML-шаблоны, клиент GigaChat и почтовая очередь. Это аудит перечисленных участков, а не гарантия отсутствия всех уязвимостей.

## Исправления

SEC-01, средний: публичные /docs, /redoc, /openapi.json отключены внутри FastAPI в production (backend/app/main.py, создание приложения). nginx уже блокировал эти URL, но внутренний сервис их обслуживал.

SEC-02, средний: добавлен TrustedHostMiddleware в production (backend/app/main.py). Разрешены имена из публичного адреса/явных CORS origins и локальные имена для healthcheck; произвольный Host больше не принимается.

SEC-03, средний: добавлен CSP на nginx для HTML и API (deploy/nginx-app.conf). script-src self, object-src none, base-uri self, form-action self; PDF preview разрешён через blob. inline стили оставлены для существующих индикаторов прогресса; inline скрипты запрещены.

## Защита новой интеграции

backend/app/assistant.py: URL провайдера фиксирован, переадресации отключены, TLS проверяется. Ключ хранится только в серверном deploy/.env (600), временный токен в памяти. Ошибки не возвращают заголовки/секреты. Чат требует действующий JWT и согласие; активная попытка теста блокирует обращения независимо от UI. Квота 8/час на пользователя, 100/сутки на сайт с транзакционной блокировкой PostgreSQL; сохраняется после рестарта. В базе хранится только ID пользователя и время запроса, без текста. frontend/src/assistant.js выводит ответы через textContent, а не HTML.

## Проверенные существующие защиты

Права проектов проверяются в projects.py/project_for_access, изменение разрешено автору только в черновике. JWT проверяется по HS256, сроку, типу и версии токена; заблокированные аккаунты не допускаются (dependencies.py). Файлы имеют случайные имена, ограничения формата/объёма, проверку заголовков и структуры Office; скачивание привязано к правам проекта. SQL использует ORM, строки из форм экранируются escapeHtml при сборке шаблонов. Обнаружение антивирусом содержимого документов не реализовано и отдельно не заявляется.

## Проверки и ограничения

94 backend-теста прошли, включая 5 новых: авторизация чата, согласие и запрет лишних полей, запрет во время теста, сохранение квот, отсутствие секретов в ошибке провайдера. npm audit --omit=dev: 0 известных уязвимостей в production зависимостях на дату проверки; pip-audit по закреплённым backend/requirements.txt: известных уязвимостей не найдено. Каталоги предупреждений не доказывают отсутствие новых или ещё не опубликованных уязвимостей.

Сессии хранятся в sessionStorage и доступны при XSS; CSP и экранирование снижают риск, но миграция refresh-token в HttpOnly cookie потребует отдельного обновления протокола и защиты CSRF. Rate limiting основного API находится в памяти одного worker: при масштабировании нужен общий лимитер. Нагрузка 10 000 участников не подтверждена. Реальная отправка писем, VK ID и Zoom не подключены, поскольку учётных данных провайдеров нет.


## Обсуждения статей, 15 октября

Комментарии проходят предварительную модерацию. Публичный ответ не содержит ФИО, email или ID пользователя; администратор получает имя только в закрытой очереди. Текст отображается через экранирование HTML. Квота в пять отправлений за час проверяется под блокировкой строки пользователя и сохраняется после перезапуска. Удаление текста сохраняет минимальную запись для учёта часовой квоты. Записи за пределами окна квоты удаляются при следующей отправке этого пользователя, поэтому без новой отправки метаданные могут храниться дольше часа. При обезличивании аккаунта комментарии удаляются. Аккаунт без согласия или заблокированный пользователь не может отправлять комментарии; комментарии отключённого автора скрываются из публичного списка.

Браузерная проверка подтвердила неисполнение HTML, приватность отклонённых текстов и причины, доступность одобрённого комментария гостю и удаление автором. Это проверка перечисленных сценариев, не доказательство отсутствия всех возможных уязвимостей.

## Форма обращения, 15 октября

ContactIn использует общую валидацию InputModel: пробелы по краям удаляются до проверки длины, управляющие символы отклоняются, переносы строк в сообщении допустимы. Серверный тест проверяет сохранённые значения и отклонение пустых/скрытых символов. Форма не заменяет SMTP: обращение доступно организатору в кабинете. Полный набор backend — 123 теста, все прошли.

## Поиск работ, 15 октября

Новые параметры q/status применяются к запросу после ограничения по роли и до пагинации. q ограничен 200 символами, LIKE-метасимволы экранируются SQLAlchemy, статусы ограничены перечислением. Тесты на 105 проектах проверяют, что поиск не раскрывает чужие работы участнику, наставнику и неназначенному эксперту. Новых публичных маршрутов и прав редактирования не добавлено.

## Границы сессий в браузере, 15 октября

Устранены гонки ответов при смене аккаунта: приватный ответ проверяет текущую учётную запись после заголовков и чтения тела, старый refresh не перезаписывает новый вход, отложенный 401 не очищает чужую новую сессию. Очереди refresh разделены по исходным токенам. Локальный выход очищает профиль, проекты, документы, ответы и состояния кабинетов даже при недоступном API; отсутствие серверного подтверждения явно сообщается. Обычный выход отзывает токены на сервере, что проверено браузером. Это не устраняет ранее описанный риск хранения токенов в sessionStorage при XSS.

## Повтор файлового запроса, 15 октября

UUID загрузки не даёт доступа к файлу: авторизация и право редактирования черновика проверяются прежде поиска прежней записи. Повтор с тем же UUID проверяет идентичность проекта, владельца, имени, категории и содержимого. Чужая запись не возвращается и не перезаписывается. Некорректный UUID отклоняется при валидации формы. Идемпотентность действует при передаче upload_id; старые API-клиенты без этого поля могут создавать несколько вложений.
